# 051 수영장 목록 페이지네이션 및 상태 필터 정리

작성일: 2026-07-17

## 목적

대시보드 수영장 목록이 전체 132개 이상을 한 번에 렌더링해 스크롤이 길어지는 문제가 있었다.

또한 수영장 목록 헤더에 `전체 / 예정 / 시작 / 종료` 버튼이 있었지만, 실제로는 수영장 상태를 바꾸는 기능이 아니라 관리자용 `접수 이벤트` 필터에 연결되어 있었다. 위치상 수영장 목록 필터처럼 보여 사용자 혼동이 컸다.

이번 작업은 웹과 모바일에서 수영장 목록을 10개 단위로 페이지네이션하고, 수영장 목록에서 의미가 불명확한 이벤트 상태 필터 버튼을 제거하는 것이다.

## 변경 내용

### Web

수정 파일:

```text
frontend/src/components/DashboardClient.tsx
```

변경:

- 수영장 목록을 `10개` 단위로 표시한다.
- 하단에 `이전 / 다음` 페이지 이동 컨트롤을 추가했다.
- 현재 표시 범위를 `1-10 / 132` 형태로 보여준다.
- 가까운 순, 검색 결과처럼 목록이 바뀌면 첫 페이지로 돌아가도록 했다.
- 수영장 목록 헤더의 `전체 / 예정 / 시작 / 종료` 버튼을 제거했다.
- 관리자용 `접수 이벤트` 목록의 상태 배지는 유지했다.

### Mobile

수정 파일:

```text
mobile/App.tsx
```

변경:

- 홈 화면의 `수영장 목록`을 `10개` 단위로 표시한다.
- 하단에 `이전 / 다음` 페이지 이동 컨트롤을 추가했다.
- 현재 표시 범위를 `1-10 / 132` 형태로 보여준다.
- 앱 최초 로딩 또는 새로고침으로 목록이 다시 로드되면 첫 페이지부터 표시한다.
- `최근 모집 일정`의 상태 배지는 실제 모집 일정 상태 표시라 유지했다.

## 상태 버튼 판단

기존 웹 대시보드의 `전체 / 예정 / 시작 / 종료` 버튼은 수영장 목록 상태가 아니라 `registration_events`의 상태 필터였다.

문제:

```text
수영장 목록 헤더 안에 표시됨
-> 사용자는 수영장 목록 필터라고 이해함
-> 실제로는 아래 관리자용 접수 이벤트 목록에만 영향
-> 일반 사용자에게는 불필요하고 혼동됨
```

결정:

```text
수영장 목록 헤더에서는 제거
접수 이벤트 상태 배지는 유지
모바일 최근 모집 일정 상태 배지도 유지
```

## 후속 작업

현재는 클라이언트에서 `/api/pools` 전체를 받은 뒤 10개씩 잘라서 보여준다.

데이터가 수천 개 이상으로 늘어나면 다음 개선을 고려할 수 있다.

```text
GET /api/pools?page=0&size=10
```

즉, 현재 단계에서는 UX 개선을 위해 클라이언트 페이지네이션으로 충분하고, 데이터 규모가 커지면 서버 페이지네이션으로 전환하는 것이 좋다.
