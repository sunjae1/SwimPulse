# SwimPulse 모니터링 운영 기준표

작성일: 2026-06-07

이 문서는 Grafana 대시보드의 주요 패널을 볼 때, 어떤 수치를 정상으로 보고 어떤 수치를 위험 신호로 볼지에 대한 초기 운영 기준표입니다.

중요:

- 이 수치들은 절대 정답이 아니라 초기 기준선입니다.
- 실제 운영에서는 며칠 동안 데이터를 본 뒤 프로젝트 특성에 맞게 조정하는 것이 좋습니다.
- 공지 크롤링처럼 외부 사이트 영향을 받는 API는 일반 API보다 느릴 수 있습니다.

## 1. 패널별 기준표

### `HTTP Request Rate (req/s)`

- 의미:
  전체 백엔드 요청량
- 양호:
  평소 범위 안에서 움직임
- 주의:
  평소보다 갑자기 2배 이상 증가
- 위험:
  요청량 급증과 함께 `p95`, `5xx`, `Hikari pending`도 같이 악화
- 해석:
  요청량 증가 자체는 문제가 아닐 수 있습니다. 다른 패널 악화와 같이 봐야 합니다.

### `Nearby Pools p95 Latency`

- 의미:
  `/api/pools/nearby`의 느린 상위 5% 응답시간
- 양호:
  `0.3s` 이하
- 주의:
  `0.3s ~ 1s`
- 위험:
  `1s` 초과
- 해석:
  위치 기반 조회는 1초를 넘기기 시작하면 체감상 느리다고 느껴질 수 있습니다.

### `Notice Scan p95 Latency`

- 의미:
  `/api/pools/{poolId}/notices/scan`의 느린 상위 5% 응답시간
- 양호:
  `1s` 이하
- 주의:
  `1s ~ 3s`
- 위험:
  `3s` 초과
- 해석:
  외부 사이트 크롤링이 포함되므로 일반 API보다 느릴 수 있습니다. 그래도 3초를 넘기면 구조 개선을 검토할 만합니다.

### `Core API p95 Latency`

- 의미:
  핵심 API들의 p95 비교
- 양호:
  대부분 `0.5s` 이하
- 주의:
  특정 API만 `1s` 근처
- 위험:
  여러 API가 동시에 `1s` 이상
- 해석:
  한 API만 느리면 개별 로직 문제일 수 있고, 여러 API가 같이 느리면 공통 자원 병목일 수 있습니다.

### `Top 5 Slow APIs p95`

- 의미:
  최근 구간 기준 p95가 가장 느린 API 상위 5개
- 양호:
  상위 API가 계속 바뀌거나, 절대 수치가 낮음
- 주의:
  같은 API가 계속 상위권
- 위험:
  같은 API가 1위로 오래 유지되며 p95도 높음
- 해석:
  일시적 튐이 아니라 지속 병목 후보를 잡는 데 좋습니다.

### `HTTP 4xx Error Rate`

- 의미:
  클라이언트 오류 비율
- 양호:
  `1%` 이하
- 주의:
  `1% ~ 5%`
- 위험:
  `5%` 초과
- 해석:
  프론트 요청 파라미터 문제, 인증 실패, 잘못된 URL 호출 증가 가능성이 있습니다.

### `HTTP 5xx Error Rate`

- 의미:
  서버 오류 비율
- 양호:
  `0%`
- 주의:
  `0.5%` 이상
- 위험:
  `2%` 이상
- 해석:
  5xx는 작은 수치라도 민감하게 봐야 합니다. 운영에서는 0에 가깝게 유지하는 것이 목표입니다.

### `Hikari Pending Connections`

- 의미:
  DB 커넥션 풀에서 커넥션을 기다리는 요청 수
- 양호:
  항상 `0`
- 주의:
  순간적으로 `1~2`
- 위험:
  `3+`가 반복되거나 계속 유지
- 해석:
  DB 커넥션 부족, 느린 쿼리, 트랜잭션 장기 점유 가능성이 있습니다.

### `Hikari Connections`

- 의미:
  활성 커넥션과 idle 커넥션 상태
- 양호:
  active가 적당하고 idle도 남아 있음
- 주의:
  active가 자주 최대치 근처, idle 거의 없음
- 위험:
  active가 높게 고정되고 pending도 같이 증가
- 해석:
  DB 풀이 포화되는 조짐입니다.

### `JVM Heap`

- 의미:
  자바 힙 메모리 사용량
- 양호:
  오르내림 반복, GC 후 어느 정도 내려감
- 주의:
  사용량이 꾸준히 우상향
- 위험:
  max에 계속 근접하거나 GC 후에도 거의 안 내려감
- 해석:
  메모리 누수, 과도한 객체 생성, 캐시 누적 가능성을 의심할 수 있습니다.

### `Process CPU`

- 의미:
  백엔드 프로세스 CPU 사용량
- 양호:
  평소 낮고, 작업 시 잠깐 상승
- 주의:
  `60%` 이상 구간이 자주 보임
- 위험:
  `80%+`가 지속
- 해석:
  계산량이 많은 코드, 파싱, 직렬화, 크롤링 처리 비용 가능성이 있습니다.

### `GC Pause Rate`

- 의미:
  GC pause 이벤트 빈도
- 양호:
  낮고 안정적
- 주의:
  평소보다 눈에 띄게 증가
- 위험:
  Heap 상승과 같이 GC pause도 계속 증가
- 해석:
  메모리 압박이 실제 성능 저하로 이어질 가능성이 있습니다.

## 2. 패널 조합으로 해석하는 법

### `p95` 상승 + `5xx` 정상 + `CPU` 상승

- 해석:
  코드 계산량, 파싱, 크롤링 비용 같은 CPU 쪽 병목 가능성

### `p95` 상승 + `Hikari pending` 상승

- 해석:
  DB 병목 가능성 큼

### `p95` 상승 + `5xx` 상승

- 해석:
  단순 느림이 아니라 장애성 문제 가능성

### `Heap` 상승 + `GC pause` 상승

- 해석:
  메모리 압박 의심

### `Request rate` 급증 + 나머지 정상

- 해석:
  단순 트래픽 증가일 수 있음

## 3. 지금 프로젝트에서 특히 중요하게 볼 것

### `/api/pools/nearby`

- `p95 > 1s`
- 의미:
  사용자 체감 저하 가능성이 높음
- 권장:
  bounding box, projection query, 결과 캐시 검토

### `/api/pools/{poolId}/notices/scan`

- `p95 > 3s` 반복
- 의미:
  사용자가 공지 확인을 느리다고 느낄 가능성 큼
- 권장:
  선행 수집, stale 정책, 백그라운드 새로고침 검토

### `Hikari Pending Connections`

- `0이 아닌 순간`이 자주 보임
- 의미:
  DB 커넥션 풀 병목 조짐
- 권장:
  느린 쿼리 확인, 커넥션 풀 설정 점검

### `HTTP 5xx Error Rate`

- 조금이라도 지속적으로 보임
- 의미:
  내부 예외나 외부 연동 실패 가능성
- 권장:
  즉시 로그 확인

## 4. 운영용 한 줄 기준

- `5xx > 0.5%`면 바로 확인
- `Hikari pending > 0`이 반복되면 DB 의심
- `nearby p95 > 1s`면 사용자 체감 저하
- `notice scan p95 > 3s`면 구조 개선 후보
- `CPU 80%+ 지속`이면 병목 조사
- `Heap이 GC 후에도 잘 안 내려가면` 메모리 점검

## 5. 사용 팁

- 처음에는 절대 수치보다 평소 패턴을 먼저 익히는 것이 좋습니다.
- 1회 튐보다 반복되는 패턴을 더 중요하게 보세요.
- 하나의 패널만 보지 말고, `요청량 + p95 + 에러율 + 리소스`를 같이 봐야 해석이 정확해집니다.
- 공지 크롤링 API는 외부 사이트 상태 영향을 받으므로, 일반 CRUD API와 같은 기준으로만 보면 안 됩니다.
