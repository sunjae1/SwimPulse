# 055 모바일 홈 탐색 UX 개선

작성일: 2026-07-19

## 목적

모바일 첫 화면에서 일반 사용자가 바로 수영장을 찾고 공지를 확인할 수 있도록 화면 우선순위를 조정했다. 운영 확인용 모집 일정은 관리자에게만 노출한다.

## 변경 사항

### 1. 수영장 목록 우선 배치

홈 화면 순서를 아래처럼 정리했다.

```text
소개 이미지
-> 위치 검색
-> 수영장 목록
-> 최근 모집 일정 (ADMIN만)
```

기존에는 위치 검색 바로 아래에 최근 모집 일정이 있어, 일반 사용자의 시설 탐색 흐름을 방해했다.

### 2. 최근 모집 일정 관리자 전용

- `user.role === 'ADMIN'`일 때만 최근 모집 일정을 렌더링한다.
- 일반 사용자는 `getEvents()` API도 호출하지 않는다.
- 수영장 목록은 모든 사용자에게 동일하게 먼저 표시된다.

### 3. 가까운 순 기본 목록

- 홈 데이터 로드 후 위치 권한을 조용히 요청하고, 허용되면 현재 위치 기준 가까운 수영장 10개를 기본 목록으로 표시한다.
- 목록 안에서 `가까운 순`이 기본 선택 상태이며, `전체 보기`는 사용자가 전체 시설 목록으로 전환할 때만 선택한다.
- 위치 권한 거부, 위치 확인 실패, 주변 목록 API 실패 시에는 전체 목록으로 안전하게 전환한다.
- 위치 검색 영역 아래에 주변 수영장 목록을 중복 렌더링하던 구조는 제거했다.

### 4. 모바일 첫 화면 시각 개선

- 텍스트 중심 상단 카드를 수영장 이미지 기반 소개 영역으로 교체했다.
- 문구는 “가까운 수영장 접수를 놓치지 마세요.”와 위치/공지 확인 안내로 축소했다.
- 로그인, 마이페이지, 설정 행동은 기존대로 첫 화면에서 접근할 수 있다.

### 5. 홈페이지 출처 변경 검토 모달 개선

문제:

- 홈 화면 전용의 밝은 글자 스타일을 알림 모달도 재사용하고 있어, 흰 모달에서 설명 문구가 거의 보이지 않았다.
- `기존 공지 보기`, `새 홈페이지 확인`, `구독 검토하기`, `확인` 버튼이 하나의 줄바꿈 영역에 섞여 작은 화면에서 읽기 어려웠다.

개선:

```text
상태 / 제목
-> 읽기 쉬운 본문 메시지
-> 검토가 필요한 이유
-> 기존 공지 보기 | 새 홈페이지 확인
-> 구독 검토하기
-> 확인
```

- 모달 전용 본문 색상을 분리했다.
- 두 출처 링크는 같은 줄의 동등한 폭 버튼으로 배치했다.
- 구독 검토와 확인은 전체 폭 버튼으로 분리했다.
- 일반 푸시 모달도 어두운 본문 색상을 사용하도록 함께 수정했다.

### 6. 공지 확인 진행 상태 개선

문제:

- 공지 확인을 누르면 화면 상단에만 `busyMessage` 배너가 추가됐다.
- 사용자가 목록 아래에 있을 때 상단 배너가 콘텐츠 높이를 바꾸어 화면이 살짝 이동했다.
- 누른 카드 근처에는 진행 상태가 없어 같은 버튼을 반복해서 누를 수 있었다.

개선:

- 공지 확인 중에는 상단 배너를 추가하지 않는다.
- 누른 버튼은 `공지 확인 중...`으로 바뀌며 비활성화된다.
- 다른 시설의 공지 확인 버튼도 요청 완료 전까지 비활성화한다.
- 화면 중앙에 시설명과 함께 `공지 확인 중` 로딩 오버레이를 표시한다.
- 결과가 오면 기존 공지 상세 화면으로 자연스럽게 전환되고, 이미지 OCR 대기 상태는 상세 화면의 polling 안내가 이어서 처리한다.

생성 이미지:

- 파일: `mobile/src/assets/pool-discovery-hero.png`
- 방식: Codex image generation 도구로 생성한 실내 공공 수영장 일러스트
- 프롬프트 요약: 밝은 공공 실내 수영장, aqua/teal 계열, 텍스트·로고 없는 넓은 모바일 홈 화면용 이미지

### 7. 장소 검색 결과를 가까운 수영장 목록으로 연결

문제:

- 모바일의 장소 검색은 `/api/locations/search` 결과 후보만 표시했다.
- 사용자가 후보를 눌러 주소를 좌표로 변환하고, 해당 위치 기준의 수영장 목록으로 전환하는 흐름이 없었다.
- 따라서 검색 버튼을 눌러도 목록이 바뀌지 않아 검색이 동작하지 않는 것처럼 보였다.

개선 흐름:

```text
장소 또는 주소 입력
-> GET /api/locations/search
-> 검색 결과 카드 자체를 눌러 기준 위치 선택
-> GET /api/locations/geocode
-> GET /api/pools/nearby + GET /api/pools/location-candidates
-> "가까운 순" 목록으로 전환
-> DB 미등록 수영장 후보는 접이식 목록으로 별도 표시
```

- 검색 중에는 버튼을 `검색 중...`으로 바꾸고 중복 요청을 막는다.
- 결과가 있으면 위치 선택 방법을, 결과가 없거나 실패하면 다음 행동을 안내한다.
- 후보 카드 전체를 기준 위치 선택 행동으로 사용한다.
- 사용자가 검색어를 고치면 이전 검색 후보와 안내 문구를 비워 현재 입력과 혼동되지 않게 했다.
- 기준 위치 검색 후보에서는 장소 홈페이지와 시설 추가 행동을 제거했다.
- 시설 추가는 기준 위치 선택 후 조회한 DB 미등록 수영장 후보에서만 제공한다.

### 8. 위치 검색 결과 시각적 구분

문제:

- 장소 검색 후보와 실제 `수영장 목록`이 같은 흰색 카드와 제목 스타일을 사용했다.
- 사용자가 현재 보고 있는 것이 위치 선택 결과인지, 실제 수영장 시설 목록인지 빠르게 구분하기 어려웠다.

개선:

- 검색 후보를 연한 하늘색 `SEARCH RESULTS` 패널 안에 그룹화했다.
- 패널 제목을 `어디를 기준으로 찾을까요?`로 두어 다음 행동을 명확히 했다.
- 각 후보에는 `기준 위치`, 카테고리 표식을 적용하고 카드 전체를 누를 수 있게 했다.
- DB 미등록 수영장 후보는 주황색 접이식 패널로 분리했다.
- 실제 수영장 목록은 기존 흰색 카드와 teal 계열 공지 확인 행동을 유지했다.

## 개발 확인 방식

일반적인 TypeScript/스타일 변경은 Android 앱을 매번 release APK로 만들 필요가 없다.

```text
디버그 앱 설치 1회
-> Metro 실행
-> 저장
-> Fast Refresh로 에뮬레이터/연결 기기에 즉시 반영
```

단, Android 네이티브 설정(Gradle, Manifest, Kotlin/Java, Firebase 설정 등) 또는 최종 release APK 검증은 다시 빌드/설치해야 한다.

## 검증 결과

| 항목 | 결과 |
|---|---|
| `npm run lint` | 통과 |
| `npx tsc --noEmit` | 통과 |
| `npm test -- --runInBand` | 통과, 1 suite / 1 test |
| 위치 검색 API 계약 | 로컬 backend에서 search, geocode, nearby 모두 정상 응답 확인 |

추가로 `emulator-5554`에 `adb reverse tcp:8081 tcp:8081`를 적용하고 Metro 개발 서버에 연결해, 새 소개 이미지와 수영장 목록 우선 배치가 로드되는 것을 확인했다.

## 수동 확인 항목

1. 일반 사용자 로그인 또는 비로그인 상태에서 홈을 연다.
2. 위치 검색 아래에 수영장 목록이 먼저 나오는지 확인한다.
3. 일반 사용자는 최근 모집 일정이 보이지 않는지 확인한다.
4. 관리자 계정에서는 수영장 목록 뒤에 최근 모집 일정이 보이는지 확인한다.
5. Fast Refresh로 첫 화면 이미지와 문구가 즉시 갱신되는지 확인한다.
6. 위치 검색에 `수원` 등 장소를 입력하고 검색한다.
7. 후보에서 `이 위치 기준 보기`를 눌러 가까운 순 목록이 해당 위치 기준으로 전환되는지 확인한다.
